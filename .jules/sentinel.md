## 2025-02-28 - Missing URL Attribute Sanitization in Semantic Compiler
**Vulnerability:** The inline compiler (`core.ts`) used a generic attribute allowlist for anchor tags without explicitly validating the semantic contents of the `href` attribute, allowing payloads like `href="javascript:alert(1)"` to be passed straight through into the final output. Additionally, external domain links lacked `target="_blank" rel="noopener noreferrer"` which exposed the application to reverse tabnabbing and referrer leakage.
**Learning:** Generic attribute filtering (e.g. `['href', 'target']`) is insufficient against semantic payload injection. URL-based attributes (`href`, `src`) must individually pass structural protocol validation before being serialized, regardless of the node being "trusted".
**Prevention:** Implement strict schema validation (using existing `isSafeUrl`) specifically on URL-bearing attributes within the AST serialization loop, and proactively force context-aware overrides (like `rel="noopener noreferrer"`) instead of relying solely on the input markup structure.
